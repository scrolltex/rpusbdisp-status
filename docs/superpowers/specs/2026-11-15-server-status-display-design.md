# Server Status Display — дизайн

Дата: 2026-11-15
Статус: на согласовании

## Зачем

На домашнем сервере (Ubuntu Server 26.04) подключён RoboPeak Mini USB Display
(320×240, RGB565, резистивный тач, USB VID:PID `fccf:a001`). Нужна программа,
которая постоянно показывает на нём состояние сервера, чтобы оценить его
одним взглядом без SSH, и позволяет пальцем листать экраны.

## Цели

- Несколько экранов, листаются свайпом влево/вправо; внизу индикатор страниц
  (точки). Тап по точке тоже переключает экран.
- Экран 1 «Общее»: имя хоста, CPU %, RAM (% и used/total), температура,
  аптайм.
- Экран 2 «Docker»: сводка (сколько running / остальных) и список всех
  контейнеров: цветная точка статуса, имя, человекочитаемый статус
  (`Up 3d`, `Exited (0)`, `Restarting`). Список прокручивается пальцем,
  если не влезает.
- Добавление нового экрана = новый класс + одна строка регистрации.
- Работает как systemd-сервис, переживает отключение/подключение дисплея и
  перезапуск Docker.

## Не цели

- Управление контейнерами (start/stop/restart) — только просмотр (решение
  пользователя).
- Графики истории, хранение метрик, веб-интерфейс, алерты.
- Поддержка нескольких дисплеев одновременно.
- Ядерный модуль `rp_usbdisplay` / fbdev.

## Анти-цели (провал, даже если «работает»)

- Интерфейс подвисает, когда Docker медленный или недоступен.
- Программа заметно грузит сервер (цель: < 2 % одного ядра в простое).
- Программа требует root для работы (кроме установки).
- Случайный тап что-то меняет на сервере.

## Ограничения

- C++ (C++17), CMake.
- LVGL v9 (git submodule).
- Программа живёт в отдельном репозитории (решение пользователя), рабочее
  имя `rpusbdisp-status`.
- Вывод и тач — через usermode SDK из `scrolltex/rpusbdisp`
  (`drivers/usermode-sdk`, с исправлениями сборки под GCC 15, которые
  пользователь пушит в свой форк), + системный `libusb-1.0`.
- Целевая система: Ubuntu Server 26.04, x86_64, GCC 15.
- Сеть на сервере есть, зависимости ставятся через apt / submodule.

## Подходы

Рассматривались три варианта; выбран **A**.

- **A. Один процесс: LVGL + usermode SDK (выбран).** Дисплей через
  `RoboPeakUsbDisplayDevice::bitblt`, тач через колбэк статуса SDK. Сбор
  метрик в фоновом потоке. Плюсы: использует уже собирающийся SDK, не зависит
  от ядра, можно добавить SDL-бэкенд для отладки на десктопе.
- **B. Ядерный модуль + LVGL fbdev/evdev.** Меньше своего кода, но модуль
  старый и почти наверняка не собирается на ядре 26.04, плюс пересборка при
  каждом обновлении ядра. Отвергнут.
- **C. Отдельные демоны сборщика и рисовалки.** Излишняя сложность для одного
  сервера и двух экранов. Отвергнут; при необходимости вырастает из A.

## Решения пользователя

- Экраны: «Общее» (CPU, RAM, температура, аптайм) и «Docker» (краткое
  состояние контейнеров); в будущем могут добавиться ещё.
- Навигация свайпом и/или кнопкой.
- Docker — только просмотр.
- Подход A.
- Горизонтальное положение; нужна возможность перевернуть на 180°.
- Отдельный репозиторий.

## Дизайн (решения автора дизайна — можно поправить)

### Расположение и SDK
Отдельный репозиторий `rpusbdisp-status`. `scrolltex/rpusbdisp` подключён
git submodule в `third_party/rpusbdisp` (закреплён на коммите с
исправлениями сборки). Исходники SDK (`infra/src`, `deps-wraps/libusbx_wrap/src`,
`rpusbdisp-drv/src` — 13 файлов) собираются собственной статической
библиотекой `rpusbdisp_sdk` в CMake проекта, без autoconf/Makefile SDK;
libusb находится через `pkg-config` (`PkgConfig::LIBUSB`). Проверено: все 13
файлов компилируются в C++17 и линкуются. Копию SDK в репозиторий не кладём —
исправления живут в одном месте.

### Структура
```
rpusbdisp-status/
  third_party/rpusbdisp       (submodule)
  CMakeLists.txt
  lv_conf.h
  third_party/lvgl            (submodule, v9.x)
  cmake/rpusbdisp_sdk.cmake   сборка SDK из исходников submodule
  third_party/json.hpp        (nlohmann/json, single header)
  src/main.cpp                цикл LVGL, разбор аргументов
  src/backend/backend.h       интерфейс: init(), flush, read_touch, alive()
  src/backend/rpusbdisp_backend.cpp
  src/backend/sdl_backend.cpp (опция -DSTATUS_SDL=ON, для отладки)
  src/data/collector.*        фоновый поток, снимок данных под mutex
  src/data/system_stats.*     /proc/stat, /proc/meminfo, /proc/uptime, температура
  src/data/docker_client.*    HTTP/1.1 GET через unix-socket /var/run/docker.sock
  src/ui/screen.h             интерфейс экрана: name(), create(parent), update(snapshot)
  src/ui/screen_overview.*
  src/ui/screen_docker.*
  src/ui/app.*                tileview + индикатор страниц + список экранов
  deploy/status-display.service
  deploy/99-rpusbdisp.rules
  README.md
```

### Вывод на дисплей
- LVGL display 320×240, `LV_COLOR_FORMAT_RGB565`, режим PARTIAL, два буфера
  по 320×40 пикселей.
- `flush_cb` → `bitblt(x, y, w, h, RoboPeakUsbDisplayBitOperationCopy, px_map)`
  (буфер области непрерывный, stride = w). Порядок байтов RGB565 проверить на
  железе на первом шаге; при необходимости — `lv_draw_sw_rgb565_swap`.
- Тач: колбэк SDK (вызывается из потока SDK) кладёт последнее
  `{x, y, pressed}` в атомарную/под mutex переменную; `read_cb` LVGL читает её.
  Координаты от устройства уже в пикселях 0..320 / 0..240 (так их использует
  ядерный драйвер), калибровка не нужна; ограничиваем значения границами экрана.
- Переподключение: если `isAlive()` = false или `openFirstDevice()` вернул
  пусто — UI продолжает работать «вслепую», раз в 2 с пробуем открыть
  устройство заново; после переподключения — `lv_obj_invalidate(lv_screen_active())`.
- Ориентация: дисплей стоит горизонтально в нормальном положении (по
  умолчанию поворот 0). Поддерживается поворот на 180° (`--rotate 180`, опция
  в unit-файле) — пользователь может перевернуть дисплей для удобства.
  Реализация: `lv_display_set_rotation(..., LV_DISPLAY_ROTATION_180)`, в
  `flush_cb` — `lv_display_rotate_area` + `lv_draw_sw_rotate` во временный
  буфер перед `bitblt`; координаты тача LVGL поворачивает сам. Вёрстка
  экранов от поворота не зависит. Повороты 90/270 не поддерживаем (другая
  геометрия, нужна иная вёрстка).
- Отключение подсветки/скринсейвер — не делаем (SDK не даёт управления
  подсветкой).

### Сбор данных
- Один фоновый поток `Collector`. Системные метрики — раз в 1 с, Docker —
  раз в 5 с. Результат — `Snapshot` (структура), копируется в UI под mutex;
  UI-таймер LVGL раз в 500 мс берёт копию и вызывает `update()` у экранов.
- CPU % — дельта `/proc/stat` между опросами (общая строка `cpu`).
- RAM — `MemTotal - MemAvailable`.
- Температура — первый найденный из: hwmon с именем `coretemp`/`k10temp`
  (`temp1_input`), иначе `thermal_zone*` с типом `x86_pkg_temp`, иначе
  `thermal_zone0`. Источник можно переопределить аргументом
  `--temp-path`. Если не найдено — показываем «—».
- Docker — `GET /containers/json?all=1` (без версии API: Docker 29+ отвергает версии ниже 1.44) через unix-сокет (без
  libcurl), таймаут 2 с на соединение и чтение. Поля: `Names[0]`, `State`,
  `Status`. Сортировка: running сверху, затем по имени. Ошибка доступа к
  сокету → на экране «Docker недоступен: <причина>», остальное работает.

### UI
- `lv_tileview` с плитками в один ряд → свайп из коробки; индикатор страниц —
  ряд точек поверх, тап по точке → `lv_tileview_set_tile_by_index`.
- Тёмная тема, крупные шрифты Montserrat (14/20/28) с кириллицей не нужна —
  тексты на английском (`CPU`, `RAM`, `Up 3d`) — решение автора, проще шрифты.
- Цвета статусов: зелёный < 70 %, жёлтый 70–90 %, красный > 90 % для CPU/RAM;
  температура: < 65 °C зелёный, 65–80 жёлтый, > 80 красный. Docker: running —
  зелёный, restarting/paused — жёлтый, exited/dead — красный (exited (0) —
  серый).
- Экран «Общее»: строка заголовка (hostname слева, аптайм справа), бары
  CPU и RAM с подписями, крупное число температуры.
- Экран «Docker»: строка сводки + `lv_list` с прокруткой.

### Разработка и проверка на железе
- Исполнитель не имеет доступа к дисплею и серверу: на железе запускает только
  пользователь. Поэтому SDL-бэкенд — основной способ разработки UI, а не
  опция «на потом».
- Первый шаг плана — маленькая утилита `hwcheck` (без LVGL): рисует
  тестовую картинку с цветными полосами (проверка порядка байтов RGB565),
  печатает координаты касаний (проверка диапазона 0..320/0..240) и
  переживает отключение/подключение кабеля. Пользователь запускает и
  сообщает результат; дальше UI строится на подтверждённых допущениях.

### Запуск и права
- Аргументы: `--backend rpusbdisp|sdl`, `--rotate 0|180`, `--temp-path PATH`,
  `--docker-socket PATH`.
- systemd unit от отдельного пользователя `statusdisp`, состоящего в группах
  `plugdev` (USB через udev-правило) и `docker` (чтение docker.sock),
  `Restart=always`.
- Установка (решение автора): `cmake --install` кладёт бинарник в
  `/usr/local/bin`, unit и udev-правило; скрипт `deploy/install.sh` создаёт
  пользователя `statusdisp`, добавляет в группы, перезагружает udev и
  включает сервис. Пакет .deb не делаем.
- Замечание по безопасности: группа `docker` фактически равна root. Программа
  делает только GET-запросы, но это стоит понимать. Альтернатива на будущее —
  read-only прокси сокета (например, docker-socket-proxy); сейчас не делаем.

### Тесты
- Юнит-тесты (без железа) для парсеров: `/proc/stat`, `/proc/meminfo`,
  разбор HTTP-ответа (в т.ч. `Transfer-Encoding: chunked`), JSON контейнеров,
  форматирование аптайма. Фикстуры — текстовые файлы.
- UI проверяется вручную через SDL-бэкенд и на железе.

## Оставлено исполнителю

- Точная вёрстка и размеры шрифтов в пределах описанного.
- Версия LVGL 9.x (последняя стабильная), фреймворк тестов (doctest/Catch2,
  header-only).
- Внутреннее устройство HTTP-клиента в пределах «GET через unix-сокет,
  таймаут, chunked».
